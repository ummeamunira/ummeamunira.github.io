SQL Track · Retail Dataset · 10 Questions
Q1Calculate total revenue by region, ordered highest to lowest.
AggregationGROUP BY
Basic›
Join orders to order_items. SUM revenue grouped by region. Apply discount before summing to get net revenue.
SELECT o.region, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS total_revenue FROM orders o JOIN order_items oi ON o.order_id = oi.order_id GROUP BY o.region ORDER BY total_revenue DESC;
Q2Find the top 5 customers by total lifetime spend.
JOINAggregation
Basic›
Three-table join: customers → orders → order_items. SUM spend per customer, ORDER BY DESC, LIMIT 5.
SELECT c.customer_id, c.name, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS total_spend FROM customers c JOIN orders o ON c.customer_id = o.customer_id JOIN order_items oi ON o.order_id = oi.order_id GROUP BY c.customer_id, c.name ORDER BY total_spend DESC LIMIT 5;
Q3Monthly order count and total revenue for the last 12 months.
DATE functionsAggregation
Basic›
DATE_TRUNC('month', order_date) groups by month. Filter with WHERE order_date >= CURRENT_DATE - INTERVAL '12 months'.
SELECT DATE_TRUNC('month', o.order_date) AS month, COUNT(DISTINCT o.order_id) AS order_count, SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS revenue FROM orders o JOIN order_items oi ON o.order_id = oi.order_id WHERE o.order_date >= CURRENT_DATE - INTERVAL '12 months' GROUP BY 1 ORDER BY 1;

Q430-day rolling average revenue by region.
Window FnRolling Avg
Intermediate›
Aggregate daily revenue by region in a CTE first. Then apply AVG() OVER with ROWS BETWEEN 29 PRECEDING AND CURRENT ROW.
WITH daily AS ( SELECT o.region, DATE_TRUNC('day', o.order_date) AS day, SUM(oi.quantity * oi.unit_price) AS revenue FROM orders o JOIN order_items oi ON o.order_id = oi.order_id GROUP BY 1, 2 ) SELECT region, day, revenue, AVG(revenue) OVER ( PARTITION BY region ORDER BY day ROWS BETWEEN 29 PRECEDING AND CURRENT ROW ) AS rolling_30d_avg FROM daily;
Q9Flag weeks where sales drop >15% below the 4-week rolling average — an anomaly detection pattern.
AnomalyWindow Fn
Advanced›
Weekly revenue CTE first. AVG() OVER with ROWS BETWEEN 4 PRECEDING AND 1 PRECEDING. Filter WHERE revenue < rolling_avg * 0.85.
WITH weekly AS ( SELECT o.region, DATE_TRUNC('week', o.order_date) AS week, SUM(oi.quantity * oi.unit_price) AS revenue FROM orders o JOIN order_items oi ON o.order_id = oi.order_id GROUP BY 1, 2 ), with_avg AS ( SELECT *, AVG(revenue) OVER ( PARTITION BY region ORDER BY week ROWS BETWEEN 4 PRECEDING AND 1 PRECEDING ) AS rolling_4w_avg FROM weekly ) SELECT *, 'ANOMALY' AS flag FROM with_avg WHERE revenue < rolling_4w_avg * 0.85; -- Same pattern as gas distribution anomaly detection

What I'm Building Toward

The infrastructure
layer that's missing.

Mid-market gas distribution utilities — the companies serving 50,000 to 500,000 customers — have a forecasting problem nobody is solving well.

They're too small to build sophisticated ML forecasting systems in-house. Too operationally complex for generic time-series tools to work out of the box. And the enterprise vendors selling to large utilities aren't interested in scoping down for a mid-market customer.

The result: utilities run demand forecasting on tools built in a previous era, submit load forecasts to regulators that don't reflect structural changes in their customer base, and make infrastructure investments based on planning models calibrated before electrification was a real variable.

I've spent the last several years building forecasting systems from inside this problem. I know what good infrastructure looks like, what it costs not to have it, and what it would take to build it as a product.

If you're thinking about this market — as an operator who lives this problem, an investor building a thesis around utility infrastructure, or a builder who wants to work on it — I'd like to talk.
